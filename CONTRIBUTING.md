# Contributing to Internacia Datasets

Thank you for contributing. This repository is **data-as-code**: the YAML files under `data/countries/`, `data/intblocks/`, and `data/blocktypes/` are the authoritative sources. Everything under `data/datasets/` is generated by the build.

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
pre-commit install   # optional but recommended
```

## Editing data

### Countries (`data/countries/*.yaml`)

- One file per entity, named by ISO 3166-1 alpha-2 code (e.g. `US.yaml`).
- Required fields: `code`, `name`, `iso3code`, `numeric_code`, `entity_type`, `code_status` (see `data/schemas/countries.schema.json`).
- Non-ISO codes need explicit `code_status` (`user_assigned`, `obsolete`) and a `recognition_status` block — see [docs/country-code-policy.md](docs/country-code-policy.md).
- `population`/`area`/`gini` are structs: `{value, year, source, source_id}`. **Never use `year: 0`** — omit the year if unknown.
- Add a `provenance` entry whenever you set or update an enriched field.
- See [docs/enrichment.md](docs/enrichment.md) for refresh cadence and maintainer commands.

### Intblocks (`data/intblocks/<category>/*.yaml`)

- One file per organization; the filename should match the record `id`, which must be **unique across all categories**.
- Required fields: `id`, `name`, `blocktype`, `status` (see `data/schemas/intblocks.schema.json`).
- Every `blocktype` value must exist in `data/blocktypes/blocktypes.yaml`.
- `includes[].id` is authoritative (ISO alpha-2 for countries); `name` is a display label.
- Dissolved organizations: set `status: historical` and a `dissolved` date. Do not invent membership lists — leave `includes` empty for records that still need research.
- **Quote YAML-boolean lookalikes**: write `'NO'` (Norway) and `'no'` (Norwegian), otherwise YAML parses them as `false`.

## Validating your changes

Run before opening a PR:

```bash
python scripts/validate_countries.py     # schema, completeness, cross-references
python scripts/validate_intblocks.py     # schema, taxonomy, duplicates, completeness
pytest tests/                            # unit and integration tests
ruff check scripts/ tests/               # lint
python scripts/builder.py build --formats parquet,duckdb   # full build check
```

CI runs the same checks on every pull request (`.github/workflows/validate.yml`).

## Pull request checklist

- [ ] Validation passes with 0 errors (`validate_countries.py`, `validate_intblocks.py`)
- [ ] Tests pass (`pytest tests/`)
- [ ] New/changed enriched fields have `provenance` entries (countries)
- [ ] Sources for membership or status changes are cited in the PR description
- [ ] `CHANGELOG.md` updated under `[Unreleased]` for schema or semantic changes

## Larger changes

New capabilities, schema changes, or breaking changes go through an OpenSpec proposal first — see [openspec/AGENTS.md](openspec/AGENTS.md).

## Releases

Maintainers tag releases (`vX.Y.Z`); `.github/workflows/release.yml` rebuilds all formats and attaches them as release assets. Versioning follows [SemVer](https://semver.org/) with migration notes in `CHANGELOG.md`.
